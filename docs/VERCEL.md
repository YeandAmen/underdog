# Vercel operations

Production: https://underdog-fyield1.vercel.app

The native Go runtime builds `cmd/server`, serves the embedded interface, and
listens on `PORT`. Production uses Neon Postgres through `DATABASE_URL`.
Local SQLite data remains under `data/`; it is not bundled into the deployment.
Neon stores the normalized events, manifests, policy snapshots, model trees,
review notes, and original import payloads. Large originals can be retained as
ordered binary chunks without sending a huge single SQL parameter.

The build includes pinned OpenCode for the optional in-process CLI backend.
Production selects the `worker` backend: Neon stores durable report jobs, and
the connected Go/OpenCode repo worker generates and publishes their reports
through authenticated HTTPS endpoints. The browser polls progress and shows
worker availability. Worker sessions are isolated and cleaned up on completion.

## Provider configuration

Production is configured for:

```dotenv
IDENTITYSHIELD_AI_PROVIDER=agentrouter
UNDERDOG_AI_BACKEND=worker
UNDERDOG_WORKER_TOKEN=<private repo-worker credential>
IDENTITYSHIELD_AI_MODEL=<configured-model-id>
IDENTITYSHIELD_AI_BASE_URL=https://agentrouter.org/v1
AGENT_ROUTER_API_KEY=<server-side credential>
KAGGLE_API_TOKEN=<server-side credential>
DATABASE_URL=<Neon integration connection>
IDENTITYSHIELD_ACCESS_TOKEN=<owner workspace token>
IDENTITYSHIELD_PUBLIC_ACCESS=true
```

`cmd/deploy -action env` reads local ignored credentials and sends them to Vercel
without printing their values. Vercel's native Neon integration provisions the
database credentials. `.env`, `.env.local`, and `.vercel` metadata are ignored.

## Commands

```sh
npx vercel link --project underdog --yes
go run ./cmd/deploy -action worker-env
npx vercel install neon --non-interactive
go run ./cmd/deploy -action verify
go run ./cmd/deploy -action migrate
go run ./cmd/deploy -action payloads
go run ./cmd/deploy -action env
npx vercel --prod --yes
go run ./cmd/deploy -action check-web
go run ./cmd/underdog worker
```

The HTTPS SQL migration path can run in development environments that restrict
outbound PostgreSQL TCP connections. The deployed Go server uses native Postgres
connections. Migration is idempotent by event ID and original-payload hash.
Whole-run/day model boundaries and existing reviewer labels remain intact.

## Access and verification

Production is a public interactive demo and opens without a Vercel login or
workspace-token prompt. `IDENTITYSHIELD_PUBLIC_ACCESS=true` explicitly disables
the public office-view token gate. Research, source data, raw records, training,
and bulk downloads still require the owner token. Model/Kaggle credentials remain server-side. Vercel
authentication protects previews only. For a private deployment, set public
access to `false` and use the workspace bearer token.

`check-web` reads local credentials and prints only counts and provider/model
status. Verify public access separately with a normal unauthenticated request.

The supplied credential and native OpenCode client reach our model from the
repo machine. Both official provider hosts return a browser challenge to Vercel
and a fresh cloud terminal. Production therefore routes fresh generation to
the authenticated repo worker. Keep that machine and worker online; saved
reports remain in Neon and are available independently of the worker.

`worker-env` creates the private worker token without printing it and configures
production to use the queue. Local `.env` keeps `UNDERDOG_AI_BACKEND=opencode`.
The worker checks the workspace's model identity, claims an exclusive job lease,
and sends only the prepared normalized evidence to its OpenCode process.
Completion rechecks current evidence and citations before saving.

A real report generated by the local Go client can be published with:

```sh
go run ./cmd/deploy -action publish-report -incident CASE-fb0f5d9b
```

Publishing checks the production evidence digest and every citation, then writes
only that report. The public report endpoint reuses a validated saved report
when its evidence digest, provider, and model still match. Local evidence briefs
and Go anomaly inference remain available independently of the provider.
